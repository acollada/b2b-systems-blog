# Gestión avanzada de eventos y suscripciones (Event Subscribers) en Microsoft Dynamics 365 Business Central  

> **Autor:** *Especialista en AL*  
> **Fecha:** 13‑Nov‑2026  

---  

## 1. Requisitos previos, contexto técnico y arquitectura en Business Central  

| Tema | Detalle |
|------|---------|
| **Entorno de desarrollo** | Visual Studio Code (VS Code) con la extensión **AL Language** (versión ≥ 23.0). |
| **Versión mínima de BC** | Business Central 2023 Release Wave 2 (versión 22.x) – soporta **EventPublisher** y **EventSubscriber** con atributos de filtrado y de orden. |
| **Conexión al sandbox** | Un tenant de sandbox (o local Docker) con **symbolic links** (`app.json` → `dependencies`) para consumir objetos de la base estándar. |
| **Conocimientos obligatorios** | - Sintaxis de AL y modelo de objetos.<br>- Conceptos de **extension** vs **customization**.<br>- Modelo de **publish‑subscribe** de .NET (inspirado en C#). |
| **Arquitectura de eventos en BC** | 1. **Event Publisher** – método o trigger que lanza un evento (`[IntegrationEvent]`, `[BusinessEvent]` o `[EventPublisher]`).<br>2. **Event Subscriber** – método decorado con `[EventSubscriber]` que se registra de forma estática en tiempo de compilación.<br>3. **Mecanismo de despacho** – el runtime de AL mantiene una tabla interna de suscriptores y ejecuta los callbacks en orden de prioridad. |
| **Tipos de eventos** | - **IntegrationEvent**: orientado a extensiones externas (Web services, APIs).<br>- **BusinessEvent**: permite la suscripción desde Power Automate, Power Apps y Logic Apps.<br>- **EventPublisher** (clásico): usado dentro del código AL para extender lógica de la aplicación. |
| **Ciclo de vida** | 1. **Publicar** → 2. **Compilar** → 3. **Registrarse** (en tiempo de compilación) → 4. **Desencadenar** (en runtime) → 5. **Ejecutar** (suscriptores). |
| **Consideraciones de seguridad** | Los suscriptores se ejecutan con los mismos permisos que el **caller** del evento. Si se necesita elevar privilegios, usar `[RunOnClient]` o `[Scope]` adecuadamente. |

## 2. Paso a paso de implementación en AL  

A continuación, se describe la creación de un **evento personalizado** y su **suscripción avanzada**, con filtrado por tabla y orden de ejecución.

### 2.1. Crear una extensión de base (publisher)

1. **Inicializar el proyecto**  
   ```bash
   mkdir AdvancedEventDemo && cd AdvancedEventDemo
   yo al:extension
   ```
2. **Definir el archivo `app.json`** (versión mínima 22.0, dependencia de `Base Application`).  
3. **Crear un nuevo codeunit** llamado `MyEventPublisher`.  

### 2.2. Publicar el evento  

```al
codeunit 50100 MyEventPublisher
{
    // Publica un evento que se dispara al validar una línea de ventas.
    [IntegrationEvent(false, false)] // false = no se propaga a clientes, false = no se registra como BusinessEvent
    local procedure OnValidateSalesLine(var SalesLine: Record "Sales Line"; var IsHandled: Boolean);
    begin
        // El cuerpo está vacío: solo actúa como “hook”.
    end;
}
```

### 2.3. Invocar el evento desde la lógica estándar  

> **Tip:** No modifiques la tabla estándar; usa una **codeunit** de extensión que sobrescriba la función `OnValidate` mediante **event subscriber** (ver paso 4).  

```al
codeunit 50101 SalesLineValidatorExtension
{
    [EventSubscriber(ObjectType::Table, Database::"Sales Line", 'OnBeforeValidate', '', false, false)]
    local procedure BeforeValidateSalesLine(var Rec: Record "Sales Line")
    var
        IsHandled: Boolean;
    begin
        // Lanzamos nuestro evento personalizado.
        MyEventPublisher.OnValidateSalesLine(Rec, IsHandled);
        // Si algún suscriptor marca IsHandled = true, evitamos la lógica estándar.
        if IsHandled then
            exit;
        // ... lógica estándar adicional (si procede) ...
    end;
}
```

### 2.4. Suscribirse al evento con filtros y prioridades  

1. **Crear una codeunit** `SalesLineEventHandlers`.  
2. **Añadir varios suscriptores** con diferentes criterios:  

```al
codeunit 50102 SalesLineEventHandlers
{
    // 1️⃣ Suscriptor que se ejecuta **primero** (Priority = 1) y solo para líneas con Qty > 100.
    [EventSubscriber(ObjectType::Codeunit, Codeunit::MyEventPublisher, 'OnValidateSalesLine', '', false, false, 1)]
    local procedure HandleLargeQuantities(var SalesLine: Record "Sales Line"; var IsHandled: Boolean)
    begin
        if SalesLine.Quantity > 100 then begin
            // Aplicar descuento del 5% automáticamente.
            SalesLine."Line Discount %" := SalesLine."Line Discount %" + 5;
            IsHandled := true; // Evita que otros suscriptores modifiquen el mismo registro.
        end;
    end;

    // 2️⃣ Suscriptor que se ejecuta **después** (Priority = 100) y solo para artículos de tipo “Service”.
    [EventSubscriber(ObjectType::Codeunit, Codeunit::MyEventPublisher, 'OnValidateSalesLine', '', false, false, 100)]
    local procedure HandleServiceItems(var SalesLine: Record "Sales Line"; var IsHandled: Boolean)
    begin
        if SalesLine."No." = '' then begin
            // No hacemos nada si la línea está vacía.
            exit;
        end;

        // Filtrado por tipo de artículo (campo personalizado 'Item Category Code').
        if SalesLine."Item Category Code" = 'SERVICE' then begin
            // Añadir texto informativo en la descripción.
            SalesLine.Description := StrSubstNo('%1 (Servicio)', SalesLine.Description);
            // No marcamos IsHandled para que otros suscriptores sigan procesando.
        end;
    end;

    // 3️⃣ Suscriptor de auditoría (Priority = 200) que registra la operación en una tabla de log.
    [EventSubscriber(ObjectType::Codeunit, Codeunit::MyEventPublisher, 'OnValidateSalesLine', '', false, false, 200)]
    local procedure LogSalesLineValidation(var SalesLine: Record "Sales Line"; var IsHandled: Boolean)
    var
        EventLog: Record "My Event Log";
    begin
        EventLog.Init();
        EventLog."Entry No." := GetNextEntryNo();
        EventLog."Table ID" := Database::"Sales Line";
        EventLog."Record ID" := SalesLine.RecordId;
        EventLog."Timestamp" := CurrentDateTime();
        EventLog."User ID" := UserId;
        EventLog.Insert();
    end;

    local procedure GetNextEntryNo(): Integer
    var
        EventLog: Record "My Event Log";
    begin
        if EventLog.FindLast() then
            exit(EventLog."Entry No." + 1);
        exit(1);
    end;
}
```

### 2.5. Publicar la extensión  

```bash
al package
al publish -u <tenant-id> -p <profile>
```

### 2.6. Verificar la ejecución  

1. Crear una orden de venta con una línea de cantidad > 100 → el descuento del 5 % debe aplicarse automáticamente.  
2. Crear una línea con artículo de categoría **SERVICE** → la descripción debe modificarse.  
3. Consultar la tabla **My Event Log** para confirmar la auditoría.
