# Optimización de rendimiento en extensiones de AL mediante **QueryObjects** y filtrado eficiente  
*(Microsoft Dynamics 365 Business Central – AL)*  

---

## 1. Requisitos previos, contexto técnico y arquitectura en Business Central  

| Tema | Descripción |
|------|-------------|
| **Requisitos de entorno** | • Business Central 18 (o superior) <br>• Visual Studio Code con extensión AL Language 1.13+ <br>• Acceso a un sandbox de desarrollo <br>• Conocimiento de la arquitectura de datos de BC (AL‑object model, tables, pages, queries) |
| **Arquitectura de extensiones** | • Las extensiones se empaquetan como **.app** y se despliegan sobre la base de datos de BC sin tocar las tablas nativas. <br>• Los **Query Objects** (`query` keyword) son objetos que definen vistas de datos de manera declarativa y se ejecutan en el servidor, evitando la sobrecarga de la capa cliente. <br>• Los **QueryObjects** se pueden usar en **AL codeunits** con `Query.Run()` o en páginas y reportes con `Query.Run()` y `Query.GetRecord()` |
| **Ventajas de usar QueryObjects** | • **Optimización automática**: el motor de BC genera los índices necesarios y utiliza los índices nativos de la tabla. <br>• **Filtrado en la capa de datos**: los filtros se aplican antes de traer los datos a la memoria. <br>• **Escalabilidad**: la lógica se ejecuta en la base de datos, reduciendo la cantidad de datos transferidos. |
| **Limitaciones** | • No se pueden usar funciones de C# o lógica compleja dentro de un QueryObject. <br>• Los filtros deben ser simples (comparaciones, `Between`, `Like`). <br>• Los QueryObjects no soportan `Join` entre más de dos tablas (aunque se pueden usar `LinkedTable` en algunas versiones). |

## 2. Paso a paso de implementación en AL con listas numeradas  

1. **Definir la tabla objetivo**  
   - Si la tabla ya existe en el núcleo (por ejemplo `Customer`), no es necesario crearla.  
   - Si se necesita una tabla personalizada, defínela con el keyword `table`.

2. **Crear el QueryObject**  
   ```al
   query 50100 "Customer Sales Summary"
   {
       DataClassification = ToBeClassified;
       // Definimos la tabla principal
       TableNo = 18; // Customer
       // Definimos los campos que necesitamos
       fields
       {
           field(1; "No."; DataType::Code[20])
           field(2; "Name"; DataType::Text[100])
           field(3; "Sales Amount"; DataType::Decimal)
           field(4; "Last Order Date"; DataType::Date)
       }
       // Añadimos una tabla vinculada
       linkedtables
       {
           table(1; "Sales Header")
           {
               // Relación: CustomerNo = No
               linktype = OuterJoin;
               // Filtrado de la tabla vinculada
               fields
               {
                   field(5; "Document Type"; DataType::Option)
                   field(6; "Amount"; DataType::Decimal)
                   field(7; "Posting Date"; DataType::Date)
               }
               // Condición de vinculación
               filter(5; "Document Type") = Sales
           }
       }
       // Definimos filtros por defecto (pueden ser modificados en tiempo de ejecución)
       filter
       {
           field(1; "No.") { }
           field(4; "Last Order Date") { }
       }
       // Ordenamos los resultados
       sorting
       {
           field(3; "Sales Amount") = Descending
       }
   }
   ```

3. **Crear un Codeunit para ejecutar el QueryObject**  
   - Se usará `Query.Run()` y se recorrerá el resultado con `Query.GetRecord()`.

4. **Implementar filtrado dinámico**  
   - Los filtros se aplican antes de ejecutar el query para reducir la carga.  
   - Utilizar `Query.SetFilter(fieldNo; filterText)`.

5. **Gestionar la paginación**  
   - Para grandes volúmenes, usar `Query.GetRecord()` con un bucle y `Query.GetNext()`.

6. **Medir el rendimiento**  
   - Habilitar `Session::SetTrace()` o usar la herramienta de rendimiento de BC.  
   - Registrar tiempos de ejecución con `Timer()`.

7. **Publicar la extensión**  
   - Empaquetar con `al publish` y probar en sandbox.

## 3. Bloque de código AL de ejemplo comentado y optimizado  

```al
codeunit 50101 "Customer Sales Summary CU"
{
    TableNo = 18; // Customer
    // --------------------------------------------------------------
    // Función pública que devuelve la suma de ventas por cliente
    // con filtros dinámicos y paginación.
    // --------------------------------------------------------------
    procedure GetSalesSummary(
        CustomerNoFilter: Text[20];
        StartDate: Date;
        EndDate: Date;
        PageSize: Integer;
        var SalesSummaryRecRef: RecordRef
    )
    var
        CustomerSalesQuery: Query 50100; // "Customer Sales Summary"
        TimerStart: Integer;
        TimerEnd: Integer;
        RecRef: RecordRef;
        Rec: Record "Sales Header";
    begin
        // 1. Configuramos filtros
        if CustomerNoFilter <> '' then
            CustomerSalesQuery.SetFilter(1, CustomerNoFilter); // "No."

        // Filtro de fecha en la tabla vinculada
        if StartDate <> 0D then
            CustomerSalesQuery.SetFilter(7, StrFmt('%1..', StartDate)); // "Posting Date"
        if EndDate <> 0D then
            CustomerSalesQuery.SetFilter(7, CustomerSalesQuery.GetFilter(7) + StrFmt('..%1', EndDate));

        // 2. Iniciamos el timer
        TimerStart := Timer();

        // 3. Ejecutamos la consulta
        if CustomerSalesQuery.Run() then begin
            // 4. Obtenemos el RecordRef del resultado
            SalesSummaryRecRef := CustomerSalesQuery.GetRecordRef();
            // 5. Paginamos
            repeat
                // Procesamos cada registro
                RecRef.GetTable(SalesSummaryRecRef);
                // Ejemplo: sumar el importe
                // (en producción se haría algo más complejo)
            until CustomerSalesQuery.GetNext() = 0;
        end;

        // 6. Medimos tiempo
        TimerEnd := Timer();
        Message('Consulta completada en %1 ms', TimerEnd - TimerStart);
    end;
}
```

### Comentarios clave

| Línea | Comentario |
|-------|------------|
| `CustomerSalesQuery.SetFilter(1, CustomerNoFilter)` | Se aplica el filtro de cliente antes de la ejecución. |
| `SetFilter(7, StrFmt('%1..', StartDate))` | Se utiliza la sintaxis `..` para rango de fechas. |
| `Timer()` | Mide el tiempo de ejecución para diagnóstico. |
| `GetRecordRef()` | Devuelve un `RecordRef` que puede ser usado en páginas o reportes sin necesidad de crear una tabla temporal. |
| `GetNext()` | Permite iterar de manera eficiente sin cargar todos los registros en memoria. |

## 4. Buenas prácticas de rendimiento, escalabilidad y errores comunes a evitar  

| Área | Buenas prácticas | Errores comunes |
|------|------------------|-----------------|
| **Diseño de QueryObjects** | • Seleccionar solo los campos necesarios. <br>• Evitar `linktype = InnerJoin` cuando no se requiere la tabla vinculada (usa `OuterJoin` para evitar filtros no indexados). <br>• Utilizar `sorting` solo cuando sea imprescindible. | • Incluir campos que no se usan (incrementa el tamaño de la fila). <br>• Usar `linktype = InnerJoin` sin índices, generando escaneos completos. |
| **Filtrado** | • Aplicar filtros antes de `Run()` (no después). <br>• Utilizar filtros de rango (`..`) para fechas y números. <br>• Evitar filtros complejos (`AND`, `OR`) que el motor no puede convertir en índices. | • Filtrar en el código después de `GetRecord()` (pasa todos los registros a la capa cliente). <br>• Usar `LIKE '%abc%'` que obliga a un escaneo completo. |
