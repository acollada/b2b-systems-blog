# Diseño de Webhooks seguros para sincronización de datos entre sistemas

## 1. Requisitos previos y contexto técnico

| Elemento | Descripción | Por qué es importante |
|----------|-------------|----------------------|
| **Entendimiento de Webhooks** | Son callbacks HTTP que un servicio expone para notificar a otro cuando ocurre un evento. | La base de cualquier solución de sincronización. |
| **Protocolos de autenticación** | OAuth 2.0, JWT, HMAC, Basic Auth. | Evitar accesos no autorizados. |
| **HTTPS** | TLS/SSL (cifrado TLS 1.2+). | Protección de datos en tránsito. |
| **Rate‑limiting & back‑off** | Límites de peticiones y estrategias de reintento. | Evitar DoS y garantizar resiliencia. |
| **Sistemas de registro y monitoreo** | Log4j, ELK, Prometheus + Grafana. | Diagnóstico y auditoría. |
| **Escalabilidad** | Load balancers, colas, microservicios. | Manejar picos de eventos. |
| **Entorno de pruebas** | Sandbox, herramientas como Postman o ngrok. | Validar antes de producción. |

> **Nota**: El diseño seguro no se trata solo de cifrar la comunicación, sino también de **verificar la identidad** del emisor, **proteger la integridad** del payload y **garantizar la idempotencia** de las operaciones.

## 2. Paso a paso de implementación con listas numeradas

1. **Define el modelo de datos y la API**  
   - Identifica los eventos que dispararán el webhook (`user.created`, `order.paid`, etc.).  
   - Especifica el payload JSON (campos obligatorios, tipos, versión de la API).  
   - Documenta el endpoint de recepción (`POST /webhooks/receive`).

2. **Crea una tabla de suscriptores**  
   ```sql
   CREATE TABLE webhook_subscriptions (
       id UUID PRIMARY KEY,
       target_url TEXT NOT NULL,
       event_type TEXT NOT NULL,
       secret CHAR(64) NOT NULL,
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   );
   ```
   - `secret`: clave HMAC compartida para firmar el payload.

3. **Implementa el mecanismo de firma HMAC**  
   - Usa SHA‑256 con la clave secreta del suscriptor.  
   - Incluye la firma en la cabecera `X-Hub-Signature-256`.

4. **Configura HTTPS**  
   - Adquiere un certificado TLS válido (Let’s Encrypt, etc.).  
   - Asegúrate de que el servidor reenvíe el encabezado `X-Forwarded-Proto` si está detrás de un proxy.

5. **Desarrolla el endpoint receptor**  
   - Valida la firma antes de procesar.  
   - Si la firma no coincide → responde `401 Unauthorized`.  
   - Si la firma es válida → procesa el evento de forma **idempotente**.

6. **Implementa reintentos y back‑off**  
   - Si la respuesta del receptor es `5xx`, reintenta con exponencial back‑off (3‑5 intentos).  
   - Si el receptor devuelve `429 Too Many Requests`, respeta el encabezado `Retry-After`.

7. **Registra cada intento**  
   - Guarda en una tabla `webhook_logs` el payload, la cabecera, la respuesta y el tiempo.  
   - Esto facilita auditorías y depuraciones.

8. **Añade un mecanismo de cancelación**  
   - Permite a los clientes revocar una suscripción (`DELETE /webhooks/{id}`).  
   - Borra o inhabilita la fila en la tabla de suscriptores.

9. **Implementa un dashboard de monitorización**  
   - Métricas: tasa de éxito, latencia, tasa de fallos.  
   - Alertas: 5xx > 5% en 5 minutos, latencia > 2 s.

10. **Prueba en entorno sandbox**  
    - Usa herramientas como Postman o ngrok para simular la recepción.  
    - Verifica que la firma se valida correctamente y que los reintentos funcionan.

## 3. Bloque de código de ejemplo comentado

A continuación se muestra un ejemplo en **Python (FastAPI)** de un endpoint receptor que valida la firma HMAC y garantiza la idempotencia mediante un identificador de evento.

```python
# webhook_receiver.py
from fastapi import FastAPI, Request, HTTPException, Header
from pydantic import BaseModel
import hmac
import hashlib
import uuid
import json
import sqlite3
from datetime import datetime

app = FastAPI()

# Configuración de la clave secreta compartida
# En producción, usar un gestor de secretos (Vault, AWS Secrets Manager, etc.)
SECRET_KEY = b"supersecreto-para-hmac-sha256"

# Conexión a la base de datos (SQLite para demo)
conn = sqlite3.connect("webhooks.db", check_same_thread=False)
cursor = conn.cursor()

# Tablas (idempotencia + logs)
cursor.execute("""
CREATE TABLE IF NOT EXISTS processed_events (
    event_id TEXT PRIMARY KEY,
    processed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
""")
cursor.execute("""
CREATE TABLE IF NOT EXISTS webhook_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_id TEXT,
    payload TEXT,
    status INTEGER,
    response TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
""")
conn.commit()

class EventPayload(BaseModel):
    event_id: str
    event_type: str
    data: dict

def verify_signature(body: bytes, signature: str) -> bool:
    """Valida la firma HMAC SHA‑256."""
    digest = hmac.new(SECRET_KEY, body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(digest, signature)

@app.post("/webhooks/receive")
async def receive_webhook(
    request: Request,
    x_hub_signature_256: str = Header(...)
):
    raw_body = await request.body()
    
    # 1. Validar firma
    if not verify_signature(raw_body, x_hub_signature_256):
        raise HTTPException(status_code=401, detail="Invalid signature")
    
    # 2. Parsear payload
    try:
        payload_dict = json.loads(raw_body)
        payload = EventPayload(**payload_dict)
    except Exception as e:
        raise HTTPException(status_code=400, detail="Malformed JSON")
    
    # 3. Idempotencia: comprobar si ya se procesó el evento
    cursor.execute(
        "SELECT 1 FROM processed_events WHERE event_id = ?", (payload.event_id,)
    )
    if cursor.fetchone():
        # Evento ya procesado: respuesta 200 sin hacer nada
        cursor.execute(
            "INSERT INTO webhook_logs (event_id, payload, status, response) VALUES (?, ?, ?, ?)",
            (payload.event_id, raw_body.decode(), 200, "Already processed")
        )
        conn.commit()
        return {"status": "already_processed"}
    
    # 4. Procesar evento (ejemplo: guardar en DB)
    # Aquí iría la lógica de negocio real.
    # ...
    
    # 5. Registrar como procesado
    cursor.execute(
        "INSERT INTO processed_events (event_id) VALUES (?)", (payload.event_id,)
    )
    # 6. Log del intento
    cursor.execute(
        "INSERT INTO webhook_logs (event_id, payload, status, response) VALUES (?, ?, ?, ?)",
        (payload.event_id, raw_body.decode(), 200, "Success")
    )
    conn.commit()
    
    return {"status": "ok"}
```

### Explicación rápida

| Paso | Qué hace | Por qué |
|------|----------|---------|
| **Firma** | `verify_signature` genera HMAC y lo compara. | Garantiza que el mensaje proviene del emisor esperado. |
| **Idempotencia** | Tabla `processed_events` evita reprocesar el mismo `event_id`. | Evita duplicados cuando el emisor reenvía. |
| **Logs** | Tabla `webhook_logs` almacena cada intento. | Auditoría y depuración. |
| **Respuesta** | `200` siempre que la firma sea válida y el evento sea nuevo o ya procesado. | Los emisores esperan `200` para confirmar recepción. |

> **Tip**: En producción, sustituye SQLite por una base de datos robusta (PostgreSQL, MySQL) y usa transacciones para evitar race‑conditions.

## 4. Buenas prácticas y errores comunes a evitar

| Buenas prácticas | Por qué? | Errores comunes | Consecuencia |
|------------------|----------|-----------------|--------------|
| **Usar HTTPS/TLS siempre** | Protege datos y evita MITM. | Enviar datos por HTTP. | Interceptación de payloads. |
| **Firmar el payload con HMAC** | Verifica integridad y autenticidad. | No firmar, confiar en IP. | Acceso no autorizado. |
| **Incluir un identificador único (`event_id`)** | Permite idempotencia. | No usar `event_id`. | Procesamiento duplicado. |
| **Responder con `200 OK` para eventos procesados** | Indica que el receptor está vivo. | Responder `202` o `204`. | Emisor puede reintentar innecesariamente. |
| **Implementar back‑off exponencial** | Evita saturar el receptor. | Reintentos sin límite. | DoS, consumo de recursos. |
| **Limitar la tasa de eventos** | Evita sobrecargar el receptor. | No limitar. | Pérdida de eventos, latencia. |
| **Registrar cada intento** | Auditar y depurar. | No registrar. | Dificulta identificar fallos. |
| **Rotar claves secretas** | Previene exposición prolongada. | No rotar. | Si la clave se ve comprometida, todos los eventos son vulnerables. |
| **Validar el origen (IP, header de cliente)** | Complementa la firma. | No validar origen. | Ataques de suplantación. |
| **Usar un esquema de versión en el payload** | Permite evolución sin romper clientes. | No versionar. | Incompatibilidades. |
| **Probar en sandbox antes de producción** | Detecta errores de firma, idempotencia. | Saltar pruebas. | Fallos en producción. |

### Errores frecuentes que debes evitar

1. **Usar la misma clave secreta para todos los suscriptores**  
   - Si un suscriptor es comprometido, todos los demás se ven afectados.

2. **No manejar la latencia del receptor**  
   - Si el receptor tarda mucho, el emisor puede cerrar la conexión y perder la notificación.

3. **No usar `Retry-After`**  
   - En caso de `429` o `503`, ignorar el encabezado puede provocar reintentos agresivos.

4. **No proteger el endpoint con autenticación adicional**  
   - HMAC es suficiente, pero combinarlo con IP allowlist o token OAuth añade defensa en profundidad.

5. **No limitar la longitud del payload**  
   - Un payload masivo puede provocar ataques DoS. Establece un límite razonable y rechaza `413 Payload Too Large`.

## 5. Resumen rápido

1. **Define eventos y modelo** → `event_id`, `event_type`, `data`.  
2. **Suscripciones** → tabla con `target_url`, `secret`.  
3. **Firma HMAC** → `X-Hub-Signature-256`.  
4. **HTTPS** → TLS 1.2+.  
5. **Endpoint receptor** → valida firma, idempotencia, procesa.  
6. **Reintentos** → exponencial, back‑off, `Retry-After`.  
7. **Logs** → auditoría y monitoreo.  
8. **Pruebas** → sandbox, ngrok, Postman.  

Con estos principios y pasos, podrás diseñar webhooks seguros y robustos que permitan la sincronización de datos entre sistemas sin comprometer la integridad, disponibilidad ni confidencialidad de la información. ¡Feliz codificación!
