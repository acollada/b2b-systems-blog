# Diseño de Webhooks seguros para sincronización de datos entre sistemas

Los webhooks son la forma más ligera y eficiente de sincronizar datos en tiempo real entre servicios. Sin embargo, su naturaleza “push” los hace vulnerables a ataques de falsificación, denegación de servicio y exposición de datos sensibles. En este artículo se detalla cómo diseñar e implementar webhooks seguros, cubriendo desde los requisitos previos hasta las mejores prácticas y los errores más comunes.

> **Objetivo**: Proveer una guía técnica paso a paso para construir un sistema de webhooks robusto, con énfasis en la seguridad, la confiabilidad y la trazabilidad.

## 1. Requisitos previos y contexto técnico

| Tema | Detalle | Por qué es importante |
|------|---------|----------------------|
| **Entorno de desarrollo** | Node.js 20.x + Express 5.x (o equivalente en Python, Go, etc.) | Versión estable con soporte de ESM, mejoras de rendimiento y tipos de TS. |
| **Base de datos** | PostgreSQL 15.x (con JSONB) o MongoDB 7.x | Necesario para almacenar registros de webhook, estados y logs. |
| **Almacenamiento de secretos** | HashiCorp Vault, AWS Secrets Manager, Azure Key Vault | Evita exponer claves en código fuente. |
| **Redundancia** | Replicación de base de datos + balanceador de carga | Garantiza disponibilidad y alta disponibilidad. |
| **Sistema de colas** | RabbitMQ 3.11 o Kafka 3.x | Manejo de reintentos y procesamiento asíncrono. |
| **Certificados TLS** | Let's Encrypt, ACME, o certificado autofirmado en dev | Evita ataques MITM y garantiza integridad de la comunicación. |
| **Autenticación** | OAuth 2.0 / JWT + HMAC | Permite identificar al emisor y firmar la carga útil. |
| **Auditoría** | Registro de eventos con timestamps y hash | Permite trazabilidad y cumplimiento. |
| **Escalabilidad** | Docker + Kubernetes (opcional) | Facilita despliegue y escalado horizontal. |

## 2. Paso a paso de implementación

> **Nota**: A continuación se muestra un ejemplo en Node.js/Express con TypeScript, pero los principios son aplicables a cualquier stack.

### 2.1. Crear la tabla de registro de webhooks

```sql
CREATE TABLE webhooks (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    target_url      TEXT NOT NULL,
    secret          TEXT NOT NULL,          -- HMAC secret
    active          BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMP WITH TIME ZONE DEFAULT now(),
    last_fired_at   TIMESTAMP WITH TIME ZONE,
    last_status     TEXT,
    retry_count     INTEGER DEFAULT 0,
    max_retries     INTEGER DEFAULT 5
);
```

### 2.2. Generar y almacenar el secreto

```ts
import { randomBytes } from 'crypto';
import { client } from './db'; // PostgreSQL client

async function createWebhook(targetUrl: string) {
    const secret = randomBytes(32).toString('hex'); // 256‑bit secret
    await client.query(
        `INSERT INTO webhooks (target_url, secret) VALUES ($1, $2)`,
        [targetUrl, secret]
    );
    return { targetUrl, secret };
}
```

### 2.3. Firmar y enviar el payload

```ts
import * as https from 'https';
import * as crypto from 'crypto';

interface WebhookPayload {
    event: string;
    data: any;
    timestamp: number;
}

async function fireWebhook(id: string, payload: WebhookPayload) {
    const { rows } = await client.query(
        `SELECT target_url, secret FROM webhooks WHERE id = $1 AND active`,
        [id]
    );

    if (!rows.length) throw new Error('Webhook no encontrado o inactivo');

    const { target_url: url, secret } = rows[0];
    const body = JSON.stringify(payload);
    const signature = crypto
        .createHmac('sha256', secret)
        .update(body)
        .digest('hex');

    const options: https.RequestOptions = {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'X-Signature': signature,
            'X-Webhook-Id': id,
            'X-Event-Type': payload.event,
            'X-Timestamp': payload.timestamp.toString()
        }
    };

    const req = https.request(url, options, res => {
        // Manejar respuesta
        res.on('data', () => {});
        res.on('end', async () => {
            await client.query(
                `UPDATE webhooks SET last_fired_at = now(), last_status = $1, retry_count = 0 WHERE id = $2`,
                [res.statusCode, id]
            );
        });
    });

    req.on('error', async err => {
        console.error('Webhook failed', err);
        // Persistir error y programar reintentos
        await client.query(
            `UPDATE webhooks SET last_status = $1, retry_count = retry_count + 1 WHERE id = $2`,
            ['ERROR', id]
        );
    });

    req.write(body);
    req.end();
}
```

### 2.4. Validar la firma en el receptor

```ts
import * as express from 'express';
import * as crypto from 'crypto';

const app = express();
app.use(express.json()); // body-parser

app.post('/webhook', async (req, res) => {
    const signature = req.headers['x-signature'] as string;
    const id = req.headers['x-webhook-id'] as string;
    const event = req.headers['x-event-type'] as string;

    // Recuperar secreto
    const { rows } = await client.query(
        `SELECT secret FROM webhooks WHERE id = $1 AND active`,
        [id]
    );
    if (!rows.length) return res.status(404).send('Webhook no encontrado');

    const { secret } = rows[0];
    const body = JSON.stringify(req.body);
    const expectedSignature = crypto
        .createHmac('sha256', secret)
        .update(body)
        .digest('hex');

    if (!crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expectedSignature))) {
        return res.status(401).send('Firma inválida');
    }

    // Procesar evento
    // ...
    res.status(200).send('OK');
});
```

### 2.5. Reintentos y back‑off exponencial

```ts
async function scheduleRetry(id: string) {
    const { rows } = await client.query(
        `SELECT retry_count, max_retries FROM webhooks WHERE id = $1`,
        [id]
    );
    const { retry_count, max_retries } = rows[0];

    if (retry_count >= max_retries) {
        await client.query(`UPDATE webhooks SET active = false WHERE id = $1`, [id]);
        return;
    }

    const delay = Math.pow(2, retry_count) * 1000; // 1s, 2s, 4s, ...
    setTimeout(() => fireWebhook(id, /* payload */), delay);
}
```

## 3. Bloque de código de ejemplo comentado

```ts
/**
 * fireWebhook.ts
 *
 * Envía un webhook con firma HMAC y maneja reintentos.
 */
import * as https from 'https';
import * as crypto from 'crypto';
import { client } from './db';

interface WebhookPayload {
    event: string;   // Tipo de evento (e.g., "user.created")
    data: any;       // Cuerpo de la carga
    timestamp: number; // Unix epoch
}

/**
 * Envía un webhook a la URL registrada.
 * @param id Identificador del webhook en la BD.
 * @param payload Carga útil del evento.
 */
export async function fireWebhook(id: string, payload: WebhookPayload) {
    // 1. Obtener URL y secreto
    const { rows } = await client.query(
        `SELECT target_url, secret FROM webhooks WHERE id = $1 AND active`,
        [id]
    );
    if (!rows.length) throw new Error('Webhook no encontrado o inactivo');

    const { target_url: url, secret } = rows[0];

    // 2. Serializar y firmar
    const body = JSON.stringify(payload);
    const signature = crypto
        .createHmac('sha256', secret)
        .update(body)
        .digest('hex');

    // 3. Configurar petición HTTPS
    const options: https.RequestOptions = {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'X-Signature': signature,
            'X-Webhook-Id': id,
            'X-Event-Type': payload.event,
            'X-Timestamp': payload.timestamp.toString()
        }
    };

    // 4. Enviar
    const req = https.request(url, options, res => {
        // Respuesta exitosa
        res.on('data', () => {});
        res.on('end', async () => {
            await client.query(
                `UPDATE webhooks
                 SET last_fired_at = now(),
                     last_status = $1,
                     retry_count = 0
                 WHERE id = $2`,
                [res.statusCode, id]
            );
        });
    });

    // 5. Manejo de errores
    req.on('error', async err => {
        console.error('Webhook failed', err);
        await client.query(
            `UPDATE webhooks
             SET last_status = $1,
                 retry_count = retry_count + 1
             WHERE id = $2`,
            ['ERROR', id]
        );
        // Programar reintento
        scheduleRetry(id);
    });

    req.write(body);
    req.end();
}
```

## 4. Buenas prácticas y errores comunes a evitar

| # | Buenas prácticas | Por qué | Error común |
|---|------------------|---------|-------------|
| 1 | **Usar TLS (HTTPS) en todas las comunicaciones** | Previene ataques MITM y garantiza la confidencialidad. | Enviar webhooks en HTTP. |
| 2 | **Firmar el cuerpo con HMAC SHA‑256** | Permite verificar la integridad y autenticidad del mensaje. | No firmar o usar MD5/sha1. |
| 3 | **Incluir un timestamp y un nonce** | Previene ataques de repetición y replay. | No validar timestamp. |
| 4 | **Limitar la frecuencia de envío** (rate‑limiting) | Evita ataques DoS y abuso. | No controlar el número de peticiones. |
| 5 | **Persistir logs de auditoría con hash** | Facilita la trazabilidad y cumplimiento de normativas. | Olvidar registrar la firma. |
| 6 | **Implementar back‑off exponencial y reintentos con límite** | Evita saturar el receptor y garantiza eventual consistencia. | Reintentar indefinidamente. |
| 7 | **Validar la URL del receptor antes de registrar** | Evita registrar endpoints maliciosos. | No validar, aceptar cualquier URL. |
| 8 | **Usar un endpoint dedicado y no compartir rutas públicas** | Minimiza el surface de ataque. | Exponer `/webhook` en un endpoint genérico. |
| 9 | **Rotar secretos periódicamente** | Reduce el riesgo en caso de filtración. | Mantener el mismo secreto indefinidamente. |
