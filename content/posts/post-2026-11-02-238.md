# Diseño de Webhooks seguros para sincronización de datos entre sistemas  

Los webhooks son una forma ligera y eficiente de comunicar eventos entre aplicaciones. Cuando se usan para sincronizar datos entre sistemas, la seguridad se vuelve crítica: el atacante podría leer, modificar o falsificar las cargas útiles.  
En este artículo se detalla todo lo que necesitas saber para diseñar, implementar y mantener webhooks seguros.

> **Objetivo**: crear un webhook que reciba eventos, los valide con autenticación y firma, los procese de forma idempotente y mantenga un historial de auditoría.  

---

## 1. Requisitos previos y contexto técnico  

| Tema | Descripción | Herramientas/Conceptos clave |
|------|-------------|-----------------------------|
| **Arquitectura de la aplicación** | Dos sistemas: **Emisor** (API que dispara eventos) y **Receptor** (API que consume). Ambos pueden estar en la nube (AWS, Azure, GCP) o en entornos on‑premises. | Microservicios, REST, HTTP/HTTPS |
| **Protocolo de comunicación** | HTTP/HTTPS POST con `application/json`. | TLS 1.2+ (o TLS 1.3) |
| **Autenticación** | Se requiere autenticación mutua o una firma digital para verificar la procedencia. | HMAC‑SHA256, RSA‑PKCS1, JWT |
| **Idempotencia** | Evitar duplicados (p. ej., reenvío de un webhook tras una caída). | Idempotency-Key, deduplicación por hash |
| **Escalabilidad** | El receptor puede recibir miles de eventos por segundo. | Cola de mensajes (SQS, RabbitMQ), worker pool |
| **Auditoría** | Registrar cada solicitud y su resultado. | BD relacional, log centralizado (ELK, CloudWatch) |
| **Pruebas** | Simular ataques (replay, falsificación). | Postman, Insomnia, OWASP ZAP, custom scripts |
| **Entorno de desarrollo** | Lenguaje y framework. | Node.js + Express, Python + FastAPI, Go + Gin, etc. |

> **Nota**: Este ejemplo usa **Node.js** con **Express** y **HMAC‑SHA256** para la firma. Puedes adaptar los conceptos a cualquier stack.

## 2. Paso a paso de implementación con listas numeradas  

> **Objetivo**: crear un endpoint `/webhook` que reciba eventos de sincronización, los valide y los procese de forma segura.

### 2.1. Preparar el entorno

1. **Crear proyecto**  
   ```bash
   mkdir webhook-secure
   cd webhook-secure
   npm init -y
   npm install express body-parser crypto dotenv
   ```

2. **Definir variables de entorno**  
   ```dotenv
   # .env
   PORT=3000
   SHARED_SECRET=superSecretKey123!   # Se comparte con el emisor
   ```

3. **Crear archivo de configuración**  
   ```js
   // config.js
   require('dotenv').config();
   module.exports = {
     port: process.env.PORT || 3000,
     sharedSecret: process.env.SHARED_SECRET,
   };
   ```

### 2.2. Crear el servidor Express

```js
// server.js
const express = require('express');
const bodyParser = require('body-parser');
const crypto = require('crypto');
const { sharedSecret, port } = require('./config');

const app = express();

// Parsear JSON y mantener el cuerpo sin modificar (para firma)
app.use(bodyParser.json({
  verify: (req, res, buf) => {
    req.rawBody = buf;
  }
}));
```

### 2.3. Middleware de verificación de firma

1. **Recibir el encabezado `X-Signature`**  
2. **Calcular HMAC‑SHA256 sobre el cuerpo bruto**  
3. **Comparar con la firma recibida** (compara en tiempo constante)

```js
// middleware/verifySignature.js
const crypto = require('crypto');

module.exports = function verifySignature(secret) {
  return (req, res, next) => {
    const signature = req.headers['x-signature'];
    if (!signature) {
      return res.status(400).json({ error: 'Missing signature header' });
    }

    const hmac = crypto.createHmac('sha256', secret);
    hmac.update(req.rawBody);
    const digest = hmac.digest('hex');

    // comparación en tiempo constante
    const buffer1 = Buffer.from(digest, 'utf8');
    const buffer2 = Buffer.from(signature, 'utf8');
    if (!crypto.timingSafeEqual(buffer1, buffer2)) {
      return res.status(401).json({ error: 'Invalid signature' });
    }

    next();
  };
};
```

### 2.4. Ruta del webhook

```js
// routes/webhook.js
const express = require('express');
const router = express.Router();
const verifySignature = require('../middleware/verifySignature');
const { sharedSecret } = require('../config');
const { processEvent } = require('../services/eventProcessor');
const { logEvent } = require('../services/logger');

router.post(
  '/webhook',
  verifySignature(sharedSecret),
  async (req, res) => {
    const event = req.body;

    // Idempotencia: usar `event.id` o `event.idempotency_key`
    const idempotencyKey = event.idempotency_key || event.id;
    if (!idempotencyKey) {
      return res.status(400).json({ error: 'Missing idempotency key' });
    }

    try {
      // Registrar la solicitud antes de procesarla
      await logEvent(idempotencyKey, event, 'received');

      // Procesar el evento
      await processEvent(event);

      // Registrar éxito
      await logEvent(idempotencyKey, event, 'processed');

      res.status(200).json({ status: 'ok' });
    } catch (err) {
      // Registrar fallo
      await logEvent(idempotencyKey, event, 'failed', err.message);
      res.status(500).json({ error: 'Processing error' });
    }
  }
);

module.exports = router;
```

### 2.5. Servicio de procesamiento de eventos

```js
// services/eventProcessor.js
const { db } = require('../db'); // ORM o cliente de BD

async function processEvent(event) {
  // Ejemplo: sincronizar un registro de usuario
  if (event.type === 'user.created') {
    const { id, name, email } = event.data;
    await db.users.upsert({ id, name, email });
  } else if (event.type === 'order.updated') {
    const { orderId, status } = event.data;
    await db.orders.update(orderId, { status });
  } else {
    throw new Error(`Unsupported event type: ${event.type}`);
  }
}

module.exports = { processEvent };
```

### 2.6. Servicio de auditoría

```js
// services/logger.js
const { db } = require('../db');

async function logEvent(key, payload, status, errorMsg = null) {
  await db.webhook_logs.create({
    key,
    payload,
    status,
    error: errorMsg,
    timestamp: new Date(),
  });
}

module.exports = { logEvent };
```

### 2.7. Conectar la ruta al servidor

```js
// server.js (continuación)
const webhookRouter = require('./routes/webhook');
app.use(webhookRouter);

app.listen(port, () => {
  console.log(`Webhook listener running on port ${port}`);
});
```

### 2.8. Pruebas básicas

```bash
# Generar firma manualmente
BODY='{"id":"123","type":"user.created","data":{"id":"u1","name":"Ana","email":"ana@example.com"}}'
SECRET="superSecretKey123!"
SIGNATURE=$(printf "$BODY" | openssl dgst -sha256 -hmac "$SECRET" -binary | base64)

# Enviar
curl -X POST http://localhost:3000/webhook \
  -H "Content-Type: application/json" \
  -H "X-Signature: $SIGNATURE" \
  -d "$BODY"
```

## 3. Bloque de código de ejemplo comentado

```js
// server.js (resumen con comentarios)
const express   = require('express');
const bodyParser= require('body-parser');
const crypto    = require('crypto');
const { sharedSecret, port } = require('./config');

const app = express();

/* 1. Body‑parser con verificación de firma
   - `verify` nos da el cuerpo sin parsear (`buf`),
   - lo guardamos en `req.rawBody` para la firma
*/
app.use(bodyParser.json({
  verify: (req, res, buf) => {
    req.rawBody = buf;
  }
}));

/* 2. Middleware que valida la firma HMAC‑SHA256
   - Se extrae `X-Signature` del header
   - Se calcula HMAC sobre el cuerpo bruto
   - Se compara en tiempo constante (crypto.timingSafeEqual)
*/
function verifySignature(req, res, next) {
  const signature = req.headers['x-signature'];
  if (!signature) return res.status(400).json({ error: 'Missing signature' });

  const hmac = crypto.createHmac('sha256', sharedSecret);
  hmac.update(req.rawBody);
  const digest = hmac.digest('hex');

  const buf1 = Buffer.from(digest, 'utf8');
  const buf2 = Buffer.from(signature, 'utf8');
  if (!crypto.timingSafeEqual(buf1, buf2))
    return res.status(401).json({ error: 'Invalid signature' });

  next();
}

/* 3. Ruta principal del webhook
   - Se garantiza idempotencia con `idempotency_key`
   - Se registra el evento antes y después del procesamiento
   - Se devuelve 200 OK al emisor
*/
app.post('/webhook', verifySignature, async (req, res) => {
  const event = req.body;
  const idempotencyKey = event.idempotency_key || event.id;
  if (!idempotencyKey) return res.status(400).json({ error: 'Missing idempotency key' });

  try {
    await logEvent(idempotencyKey, event, 'received');
    await processEvent(event);
    await logEvent(idempotencyKey, event, 'processed');
    res.status(200).json({ status: 'ok' });
  } catch (err) {
    await logEvent(idempotencyKey, event, 'failed', err.message);
    res.status(500).json({ error: 'Processing error' });
  }
});

/* 4. Arrancar el servidor */
app.listen(port, () => console.log(`Webhook listener listening on ${port}`));
```

> **Tip**: Si el emisor soporta **JWT**, reemplaza el HMAC con la verificación de firma RSA y valida el `iss` y `aud`.

## 4. Buenas prácticas y errores comunes a evitar  

| Área | Buenas prácticas | Errores comunes |
|------|------------------|-----------------|
| **Seguridad** | • Usa HTTPS (TLS 1.2/1.3). <br>• Nunca expongas la clave secreta en código fuente. <br>• Cambia la clave periódicamente. <br>• Usa firmas firmadas (HMAC, RSA). | • Enviar datos sin cifrar. <br>• Usar una clave débil o compartida públicamente. <br>• Comparar firmas con `==` (vulnerable a timing attacks). |
| **Autenticación** | • Incluye un identificador de emisor (`X-Emitter-Id`). <br>• Valida que el emisor sea conocido antes de procesar. | • Confiar solo en la presencia del header `X-Signature`. <br>• No validar que el emisor esté en la lista blanca. |
| **Idempotencia** | • Usa un campo `idempotency_key` único. <br>• Almacena el estado de cada evento (procesado, fallido). <br>• Si recibes un evento duplicado, devuelve 200 OK sin procesar de nuevo. | • Procesar cada evento varias veces (p. ej., reenvío tras timeout). <br>• No registrar el key y el resultado. |
| **Escalabilidad** | • Encola las solicitudes en una cola (SQS, Kafka). <br>• Procesa los eventos en workers asíncronos. <br>• Limita la tasa de solicitudes con `rate limiting`. | • Procesar directamente en la respuesta HTTP (puede bloquear). <br>• No manejar picos de tráfico (causa de timeout). |
| **Auditoría** | • Registra `key`, `payload`, `status`, `timestamp`, `error`. <br>• Guarda logs en un sistema centralizado (ELK, CloudWatch). | • No registrar errores (pérdida de trazabilidad). <br>• Registrar datos sensibles sin anonimizar. |
| **Validación de payload** | • Valida esquema JSON (Joi, Yup). <br>• Chequea que todos los campos obligatorios existan. |
